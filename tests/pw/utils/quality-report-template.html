📖 How to read this

  • Passed — normal green tests.
  • Known-defect guards — test.fail() tests pinning a filed defect. They fail on purpose while the bug is open, so they are not a regression. Each names its issue and asserts on its own final assertion, never on a precondition.
  • Guards now passing — the bug appears fixed. This is how a closed defect announces itself without anyone re-testing by hand.
  • Flaky — failed, then passed on a retry. Does not gate the run, and is not a pass either. It is counted separately so a retry cannot quietly launder a failure into green.
  • Failed — the only bucket that gates a run.
  • Skipped — declined with a recorded reason, never a silent pass.

There is deliberately no coverage percentage here. Nothing in this run measures how much of the product the suite exercises, and a number with no definition behind it would be invented. The Specs column counts spec files that actually executed, which is a fact this run does produce. What the suite knowingly does not cover is recorded in the QA coverage ledger, kept out of this repository because it details defects that are still open.
